# Claude Code SDN-02 proposal — review and controlled adoption

**Source:** user-provided `files.zip` containing `MIGRATION-NOTES.md` and nested `src-proposed.zip` (31 nested entries). Claude's migration notes explicitly state **none of the proposed code was executed or linted** and that the live composition root, infrastructure and tests were not covered. This report distinguishes proposals from implemented facts.

## Adopted in existing current architecture

1. **Typed private credential result.** The proposal introduces `Accounts/StoredCredentials`, to keep hash material separate from the `Account` snapshot. The current app already has an owner-private `SqliteAccounts` implementation and no need for a repository interface. We adapted the idea to `Accounts/Persistence/StoredCredentials`, replacing a shape-typed associative lookup result with a readonly concrete result carrying `Account` and `string|null` hash. The nullable hash deliberately retains the existing rejection behavior for malformed stored credentials. The current `Accounts::authenticate` still performs the unknown-user dummy bcrypt verification and compare-and-swap hash upgrade. A SQLite-backed regression test exercises this boundary.
2. **Opened-file metadata.** The proposed `LocalDownloadArtifact` uses `fstat()` on the open stream instead of `filesize()` by path before `fopen()`. We adapted that to the already present private `Downloads/Storage/ReadArtifact`, checking nonempty maximum size against the actual opened stream and retaining bounded `maxBytes+1` read, explicit symlink/path check, full-length comparison, pinned SHA-256 comparison when configured, unchanged safe exception message and business-owned audit after successful read. Standalone storage tests cover empty/valid pinned binary; existing download/HTTP tests cover invalid digest, oversize, symlink and no false accepted audit.

**Security qualification:** descriptor-level size verification closes the mismatch between metadata for a pre-open path and metadata for an opened stream. It does **not**, alone, prevent every possible symlink-substitution race between path validation and `fopen()`. Never claim general filesystem TOCTOU elimination on this basis.

## Considered, not blindly imported

- **`AccountRepository` / `SqliteAccountRepository` and `ActivityEventRepository`**: the current code already has concrete, owner-private SQLite classes and separate audit write / daily read responsibilities. One generic activity repository would combine unrelated query and command concerns. A new interface for a sole implementation would not yet earn its maintenance cost.
- **`Actor` value object, `UtcDate` value object, `ActivityCursor`, `PageDirection`, `ActivityFilter`**: promising types, particularly if shared validations and cursor codec can be extracted without changing external signatures. However Claude's proposed `Statistics` rewrites public constructors, the cursor fingerprint, query code, and navigation implementation. Preserve current session-bound cursor format and read query indexes until compatibility tests and the separately dirty `Statistics.php` are reconciled.
- **`ActivityTracking/migrations/004_activity_events_append_only.sql`**: new UPDATE/DELETE-blocking triggers are an operationally significant schema migration. Requires explicit retention, purge and backup/restore policy, not incidental import; no migration added.
- **`Passwords`**: colocating password policy with bcrypt is a reasonable alternative design but would undo the existing deliberate distinction between business credential rules and concrete bcrypt mechanics. No measurable need for another renaming pass.
- **`SessionIdentity`, `SignedInAccount`, `CreateAdmin`, `Register`, `CowOffer`, `DownloadFile` replacements**: notes explicitly change authentication trim, registration/admin validation messages and exception types, signed-in factory representation, method return values and constructors. That is API/behavior migration rather than the requested internal decoupling. Existing safety behaviors and SPA JSON contract remain authoritative.
- **`LocalDownloadArtifact` pinned-digest mandatory**: sensible for production; the current composition already configures a fixed pinned SHA-256, while isolated tests and nonproduction callers intentionally permit omission. Making the constructor mandatory requires separate compatibility decision.

## Acceptance requirements

Maintain Vanilla JS-only SPA and PHP JSON backend, original MOI (`string|null`), no speculative new interfaces, original module public manifests, auth/session CSRF handling, SQLite transactional registration+audit, bounded statistics, safe binary download, and all preserved source files. Verify `composer quality`, browser and live HTTP, JavaScript frontend, backup/restore, ingress rate limiting. Do not stage unrelated concurrent `src/ActivityTracking/Statistics.php` edits, the original PhpStorm XML exports or user-owned ZIPs.

**No claim that the entire 31-file proposal has been applied or its changed behavior accepted.** It is a reviewed source of specific improvements, not an authoritative replacement of tested project state.
