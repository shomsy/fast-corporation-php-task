## Dispositions that are not defects

- No blanket Interfaces, Repository, Factory, DI container, base class, generic helpers folder or extra Logout class. There is one actual SQLite implementation, one fixed binary, and no public PHP package consumers. Concrete constructors/owner exports provide the needed seams.
- `Accounts` lifecycle coordination, `DailyReports` aggregate meaning, `DownloadFile` post-read event decision and route composition are cohesive orchestration; a line count alone is not proof of multiple change owners.
- Local test security mechanisms (CSRF, role reload, dummy bcrypt work, no plaintext secret, native warning redaction, strict session ID, fixed path/checksum, query binding, safe text rendering and role guards) are kept and covered. No new vulnerability arose from grouping files.
- Reports are bounded to 30 active UTC dates and older `page=N` compatibility remains offset based. Those are explicit performance/navigation choices in accepted ADRs, not omissions of any stated task column or plotted series; explain them clearly at interview.
- `assets/sample.exe` has SHA-256 `31a97b0f71277adbac9bfde08c935c3e97b0bfa61d59c807c0a900660080cb80`, is a fixed harmless PE placeholder, sits outside `public/`, and is never executed server-side. The user-owned root `src.zip` is not the application asset and remains unchanged.
