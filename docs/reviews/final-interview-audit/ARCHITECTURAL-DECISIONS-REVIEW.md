# Architectural decisions and implicit choices

The repository contains 29 ADRs through ADR-0029. Each was reviewed as a whole decision record, including context, owner, alternatives, cost/failure boundaries, evidence and revisit triggers. Accepted ADR history is not rewritten; this review records where a later accepted decision supersedes it. Classification: **KEEP** (still current), **IMPROVE** (clarify/current implementation refinement), **REPLACE** (superseded by a named later decision), **REMOVE** (no longer needed in current design; historical record retained), **REQUIRES EXPLICIT PRODUCT DECISION** (a product/legal/operator authority cannot be inferred from code).

Review basis includes the repository's Architecture Governance 1.7.1 and provenance copy, Compass guidance on boundaries, abstraction, information hiding, invariants, failure semantics and security, the current LLD catalog/PHP guides, and the original Jeffallan code-review, security, PHP, test, architecture, modernization and database specialist instructions. Design lenses were checked against the originals of Ousterhout's *A Philosophy of Software Design*, Fowler's *Refactoring*, Evans's *Domain-Driven Design*, Khononov's *Learning Domain-Driven Design*, and Richards/Ford's *Fundamentals of Software Architecture*. `TASK.md` remains the primary product contract; these sources inform implementation quality, not new recruiter requirements.

## Consequential implicit decisions

| Decision | Classification; problem and owner | Options, complexity and failure | Proof / interview answer |
|---|---|---|---|
| Four business owners and one modular deployable | **KEEP**; invariant/data authority at Accounts, ActivityTracking, CowOffer, Downloads. | Cohesive ownership with explicit bootstrap; a controller/service/technical folder or microservice layout creates indirection or network consistency cost without independent deploy need. | Deptrac, manifests, SQL ownership tests, one DB transaction. Explain which owner changes if credentials, audit metrics or offer behavior changes. |
| Native PHP sessions + CSRF; no JWT/token auth service | **KEEP**; same-origin app needs server-authoritative identity. | HttpOnly/SameSite cookie, rotation, CSRF binding; JWT, cookie-free auth or framework would add credential lifetime/revocation/key concerns without a client need. | request CSRF, session expiry, native persistence, ID/token rotation and authorization tests. |
| PHP 8.3 floor / Composer concrete dependencies | **KEEP**; repo uses typed PHP behavior and PSR Clock only. | Supported constraint is `^8.3`; tested locally on 8.5.5. No framework/ORM/DI container; dev-only parser, PHPUnit, PHPStan, Deptrac, Playwright, Rector. | Composer strict validation and lock audit. No version/security support beyond executed matrix should be implied. |
| Immutable forward migrations and no request-time schema writes | **KEEP**; runtime must not mutate DB on requests. | Hash-check ledger plus CLI migration; no startup auto-DDL. Business routes reject any schema ledger other than the five migrations in this release. New NULL guard uses migration004; accepted files001–003 unchanged. | migrator tamper/upgrade/idempotence, partial-schema bootstrap regression and read-only readiness probe. The explicit migration count must move with a future schema release. |
| UTC and transient cow UI state | **KEEP** as candidate interpretation, task left them open. | UTC avoids host-dependent bins; transient state avoids inventing purchases/order persistence. Other semantics need recruiter agreement. | Exact normalized timestamps and active-date report; click/reload browser behavior. |
| Public statistics pagination and bounded report filters | **KEEP / IMPROVE**. Keep reviewer UI bounded while preserving authenticated history. | Signed keyset is the sole supported navigation; report counts are active dates up to 30, current UI labels accordingly. Avoid deceptive synthetic zero days and huge UI read. | signed cursor, exact report table/graph. The stated date truncation is a product choice, not specified by task; call it out during interview. |
| Generic errors versus diagnostics | **KEEP**; do not expose SQL, filesystem, sessions or secrets. | Safe client errors, request-correlated allowlisted server diagnostics; no stdout debug stack or credential logging. | error/body and structured event tests; PII/cookie/query exclusions. |
| Binary file safety | **KEEP**; recruiter literally requests an executable download. | harmless fixed PE placeholder outside public root, fixed checksum and bounded memory; no arbitrary path/real malware/runtime execution. | source hash and real browser/save bytes. Defend that the application only serves inert demo bytes. |
| Nginx auth rate limits and deployment warnings | **KEEP** as local reference, public deployment **REQUIRES EXPLICIT OPERATOR DECISION**. | Network edge control protects auth before workers; no PHP false claim that local config is deployed. | isolated pinned-container test proves mechanism under simulated topology only. |
| Activity retention / deletion / legal use | **REQUIRES EXPLICIT PRODUCT DECISION**. Activity events contain user ID, label, actions, timestamp; owner/operator retain in local demo database. | Do not invent a 30-day TTL, legal basis, erasure policy or forensic immutability. Automatic delete/archive and forever policy each have user/privacy and recovery cost. | README/runbook explicitly mark public deployment NO-GO pending accountable retention, erasure, backup retention and access review decision. |
| Personal MOI as formatting authority | **KEEP**. Avoid perpetual reformat due competing standards. | native PhpStorm scheme for visual formatting; parser checker only nullable/postfix choices. Remove inactive competing fixer + 18 unique dev packages; preserve other locked versions. | native `reformat_file` succeeded in seven batches; original global MOI SHA unchanged; full suite verifies code semantics. |

Historical reviews, plans and ADR-0019/0015 citations are retained as dated evidence. Current pointers in README, AGENTS, architecture boundaries/enforcement and this audit identify the live SPA and closed roadmap instead of rewriting that history. The interview answer should clearly separate a proven local test from public operational readiness and a candidate assumption from the recruiter contract.
